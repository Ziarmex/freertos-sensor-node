# STM32 FreeRTOS multi-sensor node

A sensor node for **STM32 (NUCLEO-L476RG)** built the way embedded teams
structure firmware: **fixed-priority tasks** (CMSIS-RTOS2 / FreeRTOS),
**queue-decoupled stages**, a **pure-C, host-tested core**, a **DWT microsecond
timebase**, and **measured** latency/power instead of claimed numbers.

The point is not "read a sensor". It is: how do you keep a hard-period
acquisition loop jitter-free while slower stages (processing, console) can fall
behind, detect a stalled task, and sleep the core whenever there is nothing to
do?

## Task architecture

```
        (High)                   (AboveNormal)                (Normal)
  ┌──────────────┐ sample_q  ┌──────────────┐  stat_q   ┌──────────────┐
  │  acq_task    │──────────>│ process_task │─────────>│ console_task │
  │ read sensor  │  (len 16) │ sliding avg  │  (len 8) │ print + WDT  │
  │ DWT stamp    │           │ stats + e2e  │          │ heartbeat    │
  └──────────────┘           └──────────────┘          └──────────────┘
         │                                                     │
         └──────────── g_acq_heartbeat ───────────────────────┘
                     (console detects a stalled acq task)
```

- **Producer/consumer queues** isolate the fast I2C read from the slow console;
  a full sample queue drops the newest sample and logs it instead of blocking.
- **Priority assignment** (acq > process > console) prevents priority inversion.
- **Sliding windows** per channel via a pure-C ring buffer, unit-tested on host.
- **DWT timestamps** give real acquisition latency, end-to-end latency and
  schedule jitter in microseconds, printed by the node itself.
- **Low power** via FreeRTOS tickless idle (+ optional STOP2); see below.

## Hardware

| Item | Note |
|------|------|
| NUCLEO-L476RG | STM32L476RGT6, Cortex-M4F @ 80 MHz |
| BME280 breakout | I2C1: PB8 SCL / PB9 SDA, 3V3 |
| ST-Link VCP | USART2 PA2/PA3, 115200 8N1 |
| Power meter | USB power meter or INA219 for the results table |

No sensor is required: the **simulated sensor** is the default.

## Layout

```
Core/Inc, Core/Src     application code (HAL + CMSIS-RTOS2)
  app_tasks.c          queues + task creation (called from MX_FREERTOS_Init)
  acq_task.c           periodic acquisition + jitter tracking
  process_task.c       ring buffers/stats + e2e latency
  console_task.c       periodic print + heartbeat watchdog
  sensor_{sim,bme280}.c, sensor.c, sensor_driver.h
  micros.c             DWT microsecond timebase
  power_mgmt.c         PWR bring-up / sleep helper
  console.c            UART console (no float printf needed)
components/sensor_core pure C, no HAL/RTOS dependency
host_tests/            gcc + assert, runs in CI
docs/                  stm32-setup.md, architecture.md
```

`Core/`, `Drivers/`, `Middlewares/` (HAL, startup, linker script, FreeRTOS) are
generated by STM32CubeMX and **not committed** - see `docs/stm32-setup.md` for
the exact configuration and how to drop these files in.

## Build

1. Generate the CubeMX project per **[docs/stm32-setup.md](docs/stm32-setup.md)**.
2. Copy the `Core/Inc` + `Core/Src` application files into it.
3. Call `app_start();` from `MX_FREERTOS_Init()` (USER CODE block).
4. Build in STM32CubeIDE (or `make`).

For a real BME280, set in `app_config.h`:

```c
#define APP_USE_SIMULATED_SENSOR 0
```

## Host tests

```bash
make -C host_tests test
```

Covers the ring buffer (partial fill, wrap-around keeps last N, sum stability
over 100k pushes, stats after wrap, zero-capacity safety).

## Acceptance criteria

- [ ] 0 dropped samples over a 1-hour run at the configured period.
- [ ] `e2e` latency stable and bounded; jitter reported.
- [ ] Heartbeat watchdog fires when the acq task is deliberately stalled.
- [ ] Measured sleep current significantly below active current.
- [ ] Host tests pass in CI.

## Low power

The node relies on **FreeRTOS tickless idle** (enable in CubeMX): when all tasks
are blocked the kernel suppresses SysTick and the port sleeps, waking on the
next tick. `power_mgmt.c` enables the PWR clock and exposes a `WFI` helper. For
deeper savings, configure STOP2 with an RTC wake source; measure before
claiming anything.

## Limitations

- The BME280 compensation follows the datasheet but is **not** validated against
  a calibrated reference here; simulated mode is the default.
- The HAL/FreeRTOS/startup/linker files are CubeMX-generated and not committed,
  so the firmware does not compile from a bare checkout (host tests do).
- No uplink (Wi-Fi/LoRa/MQTT) yet, to keep RTOS behaviour measurable.
- The heartbeat check is a software watchdog, not the IWDG.
- Sleep savings are unmeasured until the results table is filled in.

## Roadmap

- IWDG subscription for acq/process tasks.
- Optional LoRaWAN or UART-bridge uplink as a fourth task.
- STOP2 + RTC wake with measured currents.
